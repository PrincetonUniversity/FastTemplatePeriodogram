## Provenance & cadence sample (99-object cache)

Data source: **IRSA ZTF Light Curve API** (`nph_light_curves`, by `ID=<oid>`).
The IRSA TAP `ztf_objects_dr22` summary table -- the natural magnitude-selection
path -- was **down at fetch time** (`ORA-12541: TNS:no listener`, all DRs), as was
the cone/POS spatial path; the by-oid lightcurve API worked, so the fetcher walks
oid ranges and groups g/r per ZTF field (see `fetch_ztf_cadence.py`).

Adversarial check (`check_ztf_cadence.py`, full `cadence_adversarial_check.json`):

- **99 grouped objects** over **3 ZTF fields** (486, 686, 786; dec +2, +30, +52).
- group modes: 8 genuine same-star g+r, 48 same-field-cadence pairs, 43 single-band.
- **MJD span 58202..60951 => ~2018.2..2025.8 (7.5 yr)** -- the full released ZTF
  survey baseline (a few releases past nominal DR22; the API serves the latest).
- per-object baseline median 2731 d (7.5 yr).
- per-band clean (catflags=0) epochs: **g median 626 [229..746]**, **r median
  947 [221..996]** -- hundreds of epochs, as expected for full-survey ZTF DR
  (r > g because ZTF observes r more often).
- seasonal structure: **median 7 seasons**, yearly duty ~0.88, median largest gap
  143 d -- a clear yearly visibility window.
- mag range 14.0..20.0, median magerr 0.026.
- **adversarial warnings: NONE** -- the pulled cadence is a realistic full-survey
  ZTF sample (not a handful of epochs or a single season).

### Empirical error-vs-mag model vs `exp_mag_error()`

Binned-median magerr from ~99.5k clean epochs (`ztf_error_model.py`). The empirical
ZTF sigma is **1.6-3.5x larger** than the synthetic `exp_mag_error()` defaults
across 14-18.5 mag, with a higher floor and a steeper faint-end rise:

| mag | ZTF empirical | exp_mag_error | ratio |
|---|---|---|---|
| 14.0 | 0.0160 | 0.0100 | 1.60 |
| 15.0 | 0.0178 | 0.0100 | 1.78 |
| 16.0 | 0.0178 | 0.0101 | 1.76 |
| 17.0 | 0.0226 | 0.0102 | 2.21 |
| 18.0 | 0.0324 | 0.0107 | 3.04 |
| 18.5 | 0.0388 | 0.0111 | 3.49 |

Both cadences in the recovery run use the **empirical** model, so the real-vs-
synthetic gap is the *sampling structure*, not the noise model.

## Honest caveats (this is a DRAFT, not the publication run)

- **Scale.** This committed draft is deliberately tiny (16 sources, 1 seed, 1500
  freq, 40 templates) so it completes in ~90 s and proves the real cadence plugs
  into the harness end-to-end. The absolute recovery fractions are therefore
  coarse (steps of 1/16) and grid/alias-limited and should **not** be read as
  science. A publication run needs ~256-1024 sources, several seeds, a finer grid,
  and the full 98-template universe -- and is RunPod/many-core scale, because FTP
  catalog scoring of a dense full-survey ZTF light curve is ~10x slower per source
  than the clean synthetic (the real LC has ~600-950 epochs/band; we evenly thin
  it to `n_master_epochs` here to keep the draft local).
- **Aliasing.** Over the real 7.5-yr baseline and the wide [1,5] cyc/d band the
  alias forest is severe, so every method's recovery is depressed; that is real,
  not a bug. A cleaner run narrows to the RRab band ([1.11, 2.5] cyc/d).
- **Cadence pairing.** Most objects are `same_field_cadence` (different stars,
  identical-schedule g+r), not confirmed RR Lyrae -- which is exactly what Track B
  needs (realistic sampling + error-vs-mag), and is recorded per object so it is
  never conflated with a true same-star multiband source.

## What the draft does show (qualitatively, despite the coarse scale)

- The real ZTF cadence **plugs into the harness unchanged** and yields sane,
  finite recovery numbers via the same scorer as the synthetic cadence.
- Real-cadence recovery sits **at or slightly below** the clean synthetic at this
  scale -- consistent with real ZTF being clumpier / more aliased than the tidy
  synthetic seasons.
- **FTP(PAM) >= GLS** on both cadences, and the over-flexible **MHLS_H8 is the
  weakest on the real cadence** (0.125 vs FTP 0.188) -- the expected signature
  that a learned shape prior beats an over-parameterized free shape on
  sparse/clumpy real data. A scaled run is needed to quantify the gap.
